# Rules for the project report (docs/report/)

- The report itself is written in **Vietnamese** (course deliverable); this rule file and the chat about it follow the
  usual conventions. Database identifiers and stored values are English (`STUDENT`, `usp_Enrollment_Create`,
  `N'Studying'`): quote them in `code` and explain them in Vietnamese the first time.
- The report is **generated by a script**: edit the content in `docs/report/noidung/*.py`, never the `.docx` directly
  (the next generation overwrites it). Run the whole pipeline with the `/imcp-update-report` skill.
- Each chapter is owned by one member (assignment table in `noidung/phan_dau.py`, `docs/PLAN.md`); say so in the
  result report when you change someone else's chapter.
- **Never hard-code numbers** that come from the database: use `doi_tuong()` (counts of tables, procedures, triggers,
  constraints...), `kiem_thu()` (test cases), `ket_qua()` (query results), `schema()` (data dictionary) from
  `noidung/chung.py`. The data is regenerated with `docs/report/cong_cu/xuat_du_lieu.py`.
- SQL code in the report is extracted automatically from `database/*.sql` (`sql_object`, `sql_block`) - never copy code
  by hand into the content. C++ class names quoted in the report must match the code (`StudentService`, `Permissions`,
  ...).
- Academic style, first person plural ("nhóm"), short sentences; English terms in `code` or with the Vietnamese
  meaning the first time. Inline formatting: `**bold**`, `*italic*`, `` `code` ``. Figures/tables always have a
  caption describing the content.
- Diagrams: edit the `diagrams/*.dot` source, then `dot -Tpng` into `images/diagrams/`; screenshots are produced only by
  `tools/qlttta_screenshots` in Vietnamese (the default `QLTTTA_SHOT_LANG=vi`; never by hand, so every machine yields
  the same size/data).
- After generating the PDF: check with `swift docs/report/cong_cu/kiem_tra_pdf.swift kiemtra <pdf>` (no Word field
  errors left) and look at the images of the changed pages (`... anh <pdf> <folder> <page>`).
