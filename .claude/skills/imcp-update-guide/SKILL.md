# Update the user guide (QLTTTA)

The guide is **generated by a script** (`docs/user-guide/build_user_guide.py`) from `docs/user-guide/chapters/*.py`,
like the report. Never edit `QLTTTA_User_Guide.docx` directly: the next generation overwrites it. The guide text is
Vietnamese; talk to the user in Vietnamese. Follow `.claude/rules/05-report.md` (section "User guide").

Arguments: `all` (default) | `screens` | `windows` (fill in the Windows placeholders, see step 3) | `docx` | `pdf` |
`nopdf` (everything except the PDF). A content request ("thêm phần nhập điểm") is done in step 4.

## 0. Preparation
- `git status --short`: note changes made by others - **do not** touch/stage them. Work on a `docs/...` branch from
  `origin/develop` (never on `develop`/`main` directly).
- Find what changed in the application since the guide was last generated:
  ```bash
  LAST=$(git log -1 --format=%h -- docs/user-guide/QLTTTA_User_Guide.docx)
  git diff --stat "$LAST"..HEAD -- src resources/translations database/07_seed_data.sql database/04_procedures.sql \
      database/06_security.sql scripts packaging docker-compose.yml CMakeLists.txt
  ```
  | Changed | Sections of the guide to check |
  |---|---|
  | `Permissions.cpp`, `Labels.cpp` (new/removed menu entry or role) | table 1.1 follows by itself (`FEATURES` in `chapters/common.py` reads `Labels.cpp` and the translations; a `KeyError` means a menu name without translation), `ROLES`, a section in chapter 5 + its screenshot |
  | `src/presentation/**` (buttons, dialogs, columns, filters, export) | screenshots (step 2) and the text of chapters 4-5 |
  | `resources/translations/qlttta_vi.ts` | button/menu names quoted in **bold** (always the Vietnamese UI text), message tables 4.3, 5.2, 6.2 |
  | `src/domain/entities/*.cpp` (validation), `SqlErrorMapper.cpp`, `DbMessages.cpp` | rule/message tables of 5.2 and 6.2 |
  | `DatabaseManager.cpp` (drivers), `ServerConfig.h` (defaults), `QSettingsStore.cpp`, `main.cpp` | 3.3.3, 3.4, 4.2, 6.1 |
  | `database/07_seed_data.sql` (accounts) | read automatically (`demo_accounts()`); check `ROLE_SCOPE` in `chapter4_5.py` |
  | `04_procedures.sql`, `06_security.sql` (business task, grants) | table of 5.11 |
  | `scripts/db_init.*`, `scripts/setup_dev.*`, `docker-compose.yml` | chapter 2, 3.5 and appendix A (commands must stay copy-paste correct) |
  | `packaging/**`, `scripts/package-*` | chapter 3 (file names, installer steps) |
  | `CMakeLists.txt` `VERSION` | read automatically (cover information, file names) |
- Read the code that changed before writing about it: describe what the app really does, never what it should do.

## 1. Database with fresh seed data (for `all`, `screens`)
Screenshots need the seed data, whose dates are relative to the day `db_init` runs:
```bash
docker ps --format '{{.Names}}'          # container: imcp-mssql (docker-compose.yml) or another name
SQL_PASSWORD="$(docker exec imcp-mssql printenv MSSQL_SA_PASSWORD)" ./scripts/test_all.sh --docker imcp-mssql
```
`test_all` re-initializes the database and runs every test; stop and tell the user if a step fails. Never print the
sa password. Windows without Docker: `.\scripts\test_all.ps1 -Server "localhost\SQLEXPRESS"`.

## 2. Screenshots (when the UI or the displayed data changed)
```bash
cmake --preset macos-debug -DQLTTTA_BUILD_TOOLS=ON && cmake --build --preset macos-debug
QT_QPA_PLATFORM=offscreen QLTTTA_SHOT_PASSWORD='Demo@2026' ./build/macos-debug/tools/qlttta_screenshots
git status --short docs/report/images/screens
```
- The images in `docs/report/images/screens/` are **shared with the report**. When they change, the report must be
  regenerated too (`/imcp-update-report`), or tell the user that it still shows the old images. To refresh only the
  guide, run the tool with `QLTTTA_SHOT_DIR=<temp folder>` and copy just the files the guide uses
  (`grep -o 'SCREENS / "[a-z_]*.png"' docs/user-guide/chapters/*.py`).
- A new screen needs a stable file name in `tools/screenshot_tool.cpp` first (see the `login_server_settings.png`
  example); never take app screenshots by hand.
- Look at (Read) every changed image: right screen, real data, no permission error, nothing cut off.

## 3. Placeholders and the Windows parts (`windows`)
Parts that were not checked yet are `g.placeholder("...", "Windows")` calls (yellow **[CẦN BỔ SUNG]** boxes, listed in
appendix B). List them with `grep -n "placeholder(" docs/user-guide/chapters/*.py`.
- Fill one in only after **checking it on that platform**: run the command, go through the installer/dialog, note
  the exact button names and paths. Replace the call with real content (`g.p`, `g.steps`, `g.bullets`, `g.code`,
  `g.table`, `g.tip`, `g.warning`). If something cannot be checked now, keep the placeholder and say so.
- Screenshots of non-app windows (installers, SmartScreen, SQL Server tools, Docker Desktop) are taken by the user
  (Windows: `Win+Shift+S`, saved as PNG) to `docs/user-guide/images/windows/<file name shown in the box>`; the
  `g.figure_or_placeholder(...)` call shows them on the next build. Never click system or permission dialogs
  yourself.
- When a Windows command differs from the macOS one, show both (`g.code("PowerShell (Windows)", ...)`).

## 4. Edit the content
- Chapters: `front_matter.py` (cover, information page, table of contents), `chapter1_3.py` (introduction, SQL
  Server, installation), `chapter4_5.py` (sign in, common screens, features), `chapter6.py` (troubleshooting,
  appendices). Helpers: `guide_lib.py` on top of `docs/report/report_lib.py`.
- Style: Vietnamese, practical, addressed to the reader, short numbered steps; UI names in **bold** exactly as in the
  Vietnamese UI (`qlttta_vi.ts`); commands, paths and values in `code`; the demo password is the only password ever
  written.
- Facts the code knows are read from the code (`chapters/common.py`), never typed by hand. A new fact of that kind
  (e.g. a new list of values) gets a reader function there.
- Cross references are plain text ("Bảng 1.3", "Hình 4.2", "mục 4.8"): after adding/removing a table, figure or
  section, check them with `grep -n "Bảng [0-9]\|Hình [0-9]\|mục [0-9]" docs/user-guide/chapters/*.py` against the
  generated document.

## 5. Generate the docx
```bash
python3 docs/user-guide/build_user_guide.py      # prints "(N placeholders left)"
```
Fix Python errors in `chapters/`/`guide_lib.py` and run it again.

## 6. Export the PDF (skipped with `nopdf`)
- macOS + Word: `./docs/report/tools/export_pdf.sh docs/user-guide/QLTTTA_User_Guide.docx` (updates the table of
  contents and lists, saves `QLTTTA_User_Guide.pdf` and replaces the docx with the version Word saved). If Word shows
  **"Grant File Access"**, stop and ask the user to click *Select...* and pick `docs/report/.build/QLTTTA_User_Guide.docx`;
  never click permission dialogs. If the export times out meanwhile, close the document in Word without saving
  (`osascript -e 'tell application "Microsoft Word" to close document "QLTTTA_User_Guide.docx" saving no'`) and run
  it again.
- Windows + Word: `.\docs\report\tools\export_pdf.ps1 docs\user-guide\QLTTTA_User_Guide.docx` (same steps through
  COM, hidden Word; exit code 1 = Word field errors). No Word: ask the user to open the docx in Word, answer **Yes**
  to updating the fields (or `Ctrl+A`, `F9`), save it, then *File > Save As > PDF* to
  `docs/user-guide/QLTTTA_User_Guide.pdf`.

## 7. Check the result
- macOS: `swift docs/report/tools/check_pdf.swift check docs/user-guide/QLTTTA_User_Guide.pdf "<new text>"` (exit
  code 1 = Word field errors, export again) and `... pages <pdf> <temp folder> <changed pages>`; look at
  `overview.png` and the changed pages (tables inside the margins, images not cut, no empty page).
- Windows (no swift): open the PDF, search for "Error!" / "Lỗi!" (broken fields) and look at the changed pages.
- Compare the page count and the number of placeholders with the previous version and explain the difference.

## 8. Commit and report
- Only `git add` the guide files (`docs/user-guide/`) and, if regenerated, the shared screenshots
  (`docs/report/images/screens/`) or `tools/screenshot_tool.cpp`. `docs/report/.build/` is ignored.
- Commit message in English: `docs(user-guide): <what was updated>`. Open/update the PR with `/imcp-create-pr`.
- Reply with the template of `.claude/rules/00-general-workflow.md`: sections updated, placeholders left (before →
  after), page count, real test results, what still has to be checked on the other platform.
