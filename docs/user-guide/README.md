# User guide

The installation and user guide of QLTTTA for end users (instructor, center staff, team members preparing a demo).
It is written in **Vietnamese**, like the report, and covers macOS and Windows, SQL Server in Docker or installed on
Windows, signing in and every feature per role.

- **`QLTTTA_User_Guide.pdf`** - the PDF exported from Word, to send or print.
- **`QLTTTA_User_Guide.docx`** - the Word version saved during the PDF export (table of contents and page numbers
  filled in). Do not edit it by hand: the next generation overwrites it.

## Regenerating the guide

```bash
pip3 install python-docx
python3 docs/user-guide/build_user_guide.py
./docs/report/tools/export_pdf.sh docs/user-guide/QLTTTA_User_Guide.docx   # macOS + Word
swift docs/report/tools/check_pdf.swift check docs/user-guide/QLTTTA_User_Guide.pdf
```
On Windows: run `build_user_guide.py`, open the docx in Word, press `Ctrl+A` then `F9` (update fields) and save it as
PDF with *File > Save As*.

| Component | Location |
|---|---|
| Content of the chapters | `chapters/chapter1_3.py` (introduction, SQL Server, installation), `chapters/chapter4_5.py` (sign in, features), `chapters/chapter6.py` (troubleshooting, appendices) |
| Cover page, document information, table of contents | `chapters/front_matter.py` |
| Facts read from the code | `chapters/common.py`: menu per role (`Permissions.cpp`), demo accounts (`07_seed_data.sql`), version (`CMakeLists.txt`) |
| Placeholders, tips, warnings, steps | `guide_lib.py` (on top of `docs/report/report_lib.py`) |
| App screenshots | `docs/report/images/screens/` (generated by `tools/qlttta_screenshots`, see [../SETUP.md](../SETUP.md)) |
| Screenshots taken by hand on Windows | `images/windows/` (installers, SQL Server tools; the file names are given in the placeholders) |
| Formatting template | `docs/report/template/uit_report_template.docx` (shared with the report) |

## Parts still to be written

Parts that could not be checked yet (mostly the Windows steps) are `g.placeholder("...", "Windows")` calls. They
show as yellow **[CẦN BỔ SUNG - Windows]** boxes, are listed in appendix B ("Các mục cần bổ sung") and counted on the
document information page; the build prints how many are left. To finish one, check the steps on that platform,
replace the call with the real content (`g.p`, `g.steps`, `g.bullets`, `g.code`...) and run the build again. For a
`g.figure_or_placeholder(...)` call, save the screenshot under the file name it shows: the figure replaces the
placeholder on the next build.
