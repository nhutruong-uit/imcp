## Done well

- Every new write goes through a procedure with named parameters and `execPrepared`; every new procedure is granted
  to exactly the roles that need it with positive and negative permission cases (P22-P25); every new THROW is in
  `DbMessages.cpp`.
- The new success cases compare against values computed another way (T74, T76-T80, T94, T101), on relative seed
  dates; unit tests use call recorders to prove that invalid input never reaches a repository.
- `DataPage`, `DataTable`, `FormDialog`, `Fields` and `TableDialog` removed most of the page boilerplate: rows are
  read through the proxy by column key, ids are copied before every nested event loop, colors come from `Theme`.
- The C++ permission matrix matches `06_security.sql` screen by screen (column-level GRANT on TEACHER included), and
  the layering stays clean (no SQL outside `infrastructure/repositories`).
- The Windows support is careful: every new PowerShell script parses on 5.1 with BOM/CRLF, `test_all.ps1` restores
  its environment variables, the docs explain why (SQL Server 2025, TCP/IP off), and the report/guide numbers are
  generated from the code and the database.
